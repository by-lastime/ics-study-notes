# 第 3 讲独立练习答案与评分

对应[第 3 讲：循环、跳转表与过程调用](../第3讲-循环与过程调用.md)。建议先完整写出自己的答案，再按小问核对。必做 D3-P01—D3-P04 每题 10 分，共 40 分；32 分为基础过关线。D3-P05 为选做 10 分，单独记录，不补入必做分数。

这里的分值是本套练习的训练评分，不是往年试卷的官方评分。等价 C 写法、不同但正确的推导均可得分；程序行为与边界比变量名字重要。若前一小问发生算术笔误，后续沿用该数但方法独立正确，可保留相应方法分，避免把同一个小错反复扣分。首次独立得分、得到提示后的结果和订正结果分开记录。

## D3-P01：恢复循环并核对边界（10 分）

### 1. 寄存器角色（1 分）

`%rax` 保存累计值 `sum`，`%rdx` 保存当前奇数计数器 `i`，每项 0.5 分。`%rcx` 是每轮临时算出的 `3*i`，知道它有助于理解，但本问不额外计分。

### 2. 初始化、条件、更新（2 分）

- 初始化 `sum=0,i=1`：0.5 分。
- 条件是 `i<=n`：1 分。`cmpq %rdi,%rdx` 形成 `i-n` 的条件码，`jle` 是有符号“小于或等于”。
- 每轮 `i+=2`：0.5 分。

进入循环前先 `jmp .Lp1_test`，所以第一轮也要先检查条件。把条件写成 `n<=i` 不能得条件分。

### 3. 等价 C（2 分）

```c
long loop3(long n) {
    long sum = 0;
    for (long i = 1; i <= n; i += 2) {
        sum += 3 * i;
    }
    return sum;
}
```

循环控制完整正确给 1 分，累计 `3*i` 并返回正确变量给 1 分。用 `while` 或 `goto` 的等价实现也可以；不能写成先执行一次的无入口检查 `do-while`，因为这会在 `n=0` 时改变行为。给定 `n<=100`，计算不会发生 `long` 有符号溢出。

### 4. n=5（1 分）

| 进入循环体时 i | 本轮加入 | 累计 sum | 更新后的 i |
|---:|---:|---:|---:|
| 1 | 3 | 3 | 3 |
| 3 | 9 | 12 | 5 |
| 5 | 15 | 27 | 7 |

加入的数为 `3、9、15`，给 0.5 分；最终返回 `27`，给 0.5 分。`i=7` 时条件失败，不再进入循环体。

### 5. n=0（1 分）

不执行循环体，返回零。因为初始 `i=1`，第一次先到测试位置，`1<=0` 不成立。结果正确给 0.5 分，指出入口先检查的原因给 0.5 分。

### 6. jle 改为 jl（1 分）

条件变成 `i<n`；`n=5` 时只加入 `3、9`，返回 `12`。条件变化给 0.5 分，结果给 0.5 分。差别不是机械地“少一轮”对所有输入都成立：当边界 `n` 为偶数时，奇数计数器原本也不会恰好等于它。

### 7. 循环不变式（2 分）

一种表述是：每次到达测试位置，`i` 为正奇数，`sum` 等于所有小于 `i` 的正奇数分别乘以 3 后的和，即

```text
sum = 3 × (1 + 3 + ... + (i-2))
```

`i=1` 时右侧为空和零，初始成立。若当前条件通过，循环体把 `3*i` 加入，随后 `i` 增加 2，所以新 `i` 之前的所有正奇数恰好都被累加，关系继续成立。

正确关系给 1 分，初始与保持理由合计给 1 分。也可用已执行轮数 `k` 表述 `i=1+2k,sum=3k²`，但必须解释它与执行过程的联系，不能只给一个没有定义 `k` 的公式。

## D3-P02：跳转表、默认分支与落入（10 分）

### 1. 映射（2 分）

| x | 入口标签 |
|---:|---|
| 0 | `.Lp2_a` |
| 1 | `.Lp2_b` |
| 2 | `.Lp2_default` |
| 3 | `.Lp2_c` |
| 4 | `.Lp2_c` |

五项全对 2 分；每错一项扣 0.5 分，最低零分。`x=2` 在索引范围内，但它的表项主动指向默认代码，这与范围外直接跳去默认代码是两条不同路径。

### 2. 负数为何去默认分支（1 分）

`ja` 使用无符号“大于”条件。`-1` 的 64 位位模式按无符号解释是 `2^64-1`，大于 4，因此跳去默认分支。说清无符号比较给 0.5 分，说明负数位模式落在大值区间给 0.5 分。

### 3. 共享入口与落入（1 分）

`x=3` 和 `x=4` 共用 `.Lp2_c`，0.5 分。`.Lp2_a` 完成 `a+=2` 后直接继续执行 `.Lp2_b`，对应 `case 0` 落入 `case 1`，0.5 分。不能说 0 和 1“完全相同”，因为 0 在到达共同代码前修改了参数。

### 4. 等价 C（2 分）

```c
long route(long x, long a) {
    switch (x) {
    case 0:
        a += 2;
        /* 有意落入 */
    case 1:
        return 5 * a;
    case 3:
    case 4:
        return a - 3;
    default:
        return -1;
    }
}
```

0、1 的落入和结果正确给 1 分，3、4 及默认路径正确给 1 分。`case 2` 可不单独写，因为它与默认路径一致；显式加 `case 2:return -1;` 同样正确。输入范围保证运算不溢出。

### 5. 三个返回值（1 分）

`route(0,4)=30`，`route(1,4)=20`，`route(3,4)=1`。三项全对 1 分，恰有一项错误给 0.5 分，其余零分。第一个结果需要先把 4 加 2，再乘 5。

### 6. 表项地址与内容（1 分）

读 `0x5000+4*8=0x5020`，0.5 分。该处存 `.Lp2_c` 的代码地址，不是计算结果 `a-3`，0.5 分。

### 7. 错误替换（2 分）

不能保证正确执行。`leaq .Lp2_table(,%rdi,8),%rax` 只得到表项的地址，没有读取其中的目标地址；随后的 `jmp *%rax` 将跳到表本身的那一项，把数据位置当代码入口。

指出 `lea` 得到表项地址、缺少一次内存读取给 1 分；说明会跳到表区而不是分支代码给 1 分。正确的两步等价写法可为：

```asm
movq .Lp2_table(,%rdi,8), %rax
jmp *%rax
```

这里仍按题目提供的绝对地址表模型理解。实际程序若使用位置无关代码，地址形成方式可能不同，但不能省略从表项取得目标的步骤。

## D3-P03：局部内存、调用前后与栈恢复（10 分）

### 1. 分配空间（2 分）

进入时 `%rsp=0x2008`。`pushq %rbx` 先减 8，得到 `0x2000`，并把原值 99 写入 `[0x2000]`。随后减 16，得到 `0x1ff0`。

两个 `%rsp` 各 0.5 分，旧 `%rbx` 的地址 1 分。注意十六进制地址减去十进制 16，就是减去 `0x10`。

### 2. 参数和对齐（1 分）

`%rdi=0x1ff8`，因为 `lea` 传入 `8(%rsp)` 的地址；`%rsi=5`。两参数正确给 0.5 分。调用前 `%rsp=0x1ff0`，为 16 的倍数，满足本题调用要求，给 0.5 分。

### 3. 被调用函数入口（2 分）

`call` 再压入 8 字节返回地址，故入口 `%rsp=0x1fe8`，`R1` 位于 `[0x1fe8]`。

```text
高地址
0x2008  R0：返回外层的地址
0x2000  99：保存的旧 rbx
0x1ff8  7：局部数据；rdi 指向这里
0x1ff0  已预留，题目未写入，内容未知
0x1fe8  R1：返回 caller 的地址  <- rsp
低地址
```

入口 `%rsp` 与 `R1` 位置正确给 1 分，图中另外三个已知对象的相对位置正确给 1 分。图的上下方向可以相反，但必须标明地址顺序。不能给未初始化槽擅自填零。

### 4. 返回值（1 分）

`read_add` 读出 7，加上第二参数 5，返回 `12`；它没有写回内存。`caller` 把保留的 `x=4` 加上，最终返回 `16`。各 0.5 分。

### 5. 栈与寄存器恢复（2 分）

`read_add` 的 `ret` 弹出 `R1`，回到 `caller` 时 `%rsp=0x1ff0`。随后 `addq $16` 使它成为 `0x2000`；`popq %rbx` 恢复 99，并使 `%rsp=0x2008`；最后 `caller` 的 `ret` 弹出 `R0`，回到外层时 `%rsp=0x2010`。

`read_add` 返回后的值给 0.5 分，`caller` 最终返回后的值给 1 分，`%rbx=99` 给 0.5 分。最容易错的是把 `0x2008` 当最终答案：它是执行最后 `ret` **之前**的栈顶，不是之后。

### 6. 用 rdi 保留 x 为什么错误（2 分）

本题中的 `%rdi` 在调用前就已经被 `lea` 改成局部数据地址 `0x1ff8`，所以不是 `x`。即使 `read_add` 本身不修改 `%rdi`，调用后加它也会算出 `12+0x1ff8`，不等于 `x+12`。指出这个具体覆盖给 1 分。

此外，`%rdi` 属调用者保存寄存器，普通被调用函数可以改变它。即使某段代码没有提前覆盖它，也不能仅凭 ABI 假定跨调用后仍保留原值。说明这一点给 1 分。

## D3-P04：递归每层保存什么（10 分）

### 1. 基本情形与递推（2 分）

`F(0)=0`，1 分。`n>0` 时，`lea -1(%rdi,%rdi),%rbx` 算出 `2n-1`，然后调用 `F(n-1)`，所以

```text
F(n) = (2n-1) + F(n-1)
```

递推正确给 1 分。`lea` 没有读取该数值所对应的内存。

### 2. 等价 C（1 分）

```c
long odd_sum(long n) {
    if (n == 0) return 0;
    return (2 * n - 1) + odd_sum(n - 1);
}
```

边界、递归参数与返回表达式完整正确给 1 分。虽然结果等于 `n*n`，本问要解释给定递归，不宜只写闭式函数。

### 3. odd_sum(3) 的过程（2 分）

向下：`n=3` 保留 5，`n=2` 保留 3，`n=1` 保留 1，`n=0` 直接返回 0。向上：`F(1)=1+0=1`，`F(2)=3+1=4`，`F(3)=5+4=9`。

各层保留值正确给 1 分，各层返回值正确给 1 分。只写最终 9 而无过程最多得到本问 0.5 分。

### 4. rbx 的保存约定（1 分）

父层把自己的 `2n-1` 放入 `%rbx`，期待子调用按 ABI 保持它。子层要覆盖 `%rbx` 时，先用 `push` 保存进入时的值，结束时 `pop` 恢复，因此返回父层时父层的值仍在。

父层自己也先保存了它的调用者原来的 `%rbx`，最终必须恢复。说清子层保护父层值给 0.5 分，说清当前层也要恢复自己的入层旧值给 0.5 分。仅写“递归自动保存寄存器”不得分。

### 5. 同时活跃数量（1 分）

最多同时活跃 4 个调用：`3、2、1、0` 四层。尚未配对弹出的非基本层保存操作有 3 个。各 0.5 分。基本层虽然没有执行 `push %rbx`，仍然有返回地址。

### 6. 栈顶与对齐（2 分）

每下降到下一层，先有当前层 `push %rbx` 减 8，再有 `call` 压返回地址减 8，共减少 16 字节。于是：

| 层 | 刚入口 rsp | 非基本层 push 后、call 前 rsp |
|---|---|---|
| n=3 | `0x3008` | `0x3000` |
| n=2 | `0x2ff8` | `0x2ff0` |
| n=1 | `0x2fe8` | `0x2fe0` |
| n=0 | `0x2fd8` | 基本情形不调用 |

每层减 16 的解释给 0.5 分，基本层入口 `0x2fd8` 给 1 分，三个调用前地址均对 16 余 0 的检查给 0.5 分。

也可进一步画出最深处的栈，核对“保存的是哪个层的值”：

```text
0x3008  外层返回地址
0x3000  进入最外层前的旧 rbx
0x2ff8  n=2 返回 n=3 的地址
0x2ff0  n=3 保留的值 5，被 n=2 的 push 保存
0x2fe8  n=1 返回 n=2 的地址
0x2fe0  n=2 保留的值 3，被 n=1 的 push 保存
0x2fd8  n=0 返回 n=1 的地址  <- rsp
此刻 rbx 为 n=1 保留的值 1
```

这些内部返回地址在该函数中可以是同一个指令地址，因为每层执行的是同一处递归 `call`。**地址相同不等于栈槽相同**：每次调用都把它压在不同地址，返回时按后进先出逐层弹出。

### 7. 基本情形不能多 pop（1 分）

基本情形在任何 `push %rbx` 之前就跳走，当前栈顶已经是它的返回地址。如果额外 `pop %rbx`，会把返回地址错误弹入 `%rbx`；之后 `ret` 再把上一个栈槽的数据当目标。指出没有匹配的 `push` 给 0.5 分，说明返回地址被误弹给 0.5 分。

## D3-P05：超过六个参数的调用（选做，10 分）

### 1. 前六个寄存器（1 分）

依次为 `%rdi,%rsi,%rdx,%rcx,%r8,%r9`。顺序完全正确 1 分；只对前四个给 0.5 分。

### 2. 三个栈顶时刻（2 分）

初始 `0x4000`；压入 8 后 `0x3ff8`；压入 7 后 `0x3ff0`；`call` 压入返回地址后，`eight` 入口为 `0x3fe8`。两次压栈后的值各 0.5 分，入口值 1 分。调用前 `0x3ff0` 仍满足 16 字节对齐。

### 3. 入口布局（2 分）

```text
0x4000  调用者原有数据
0x3ff8  8：第八参数  = 16(%rsp)
0x3ff0  7：第七参数  = 8(%rsp)
0x3fe8  返回地址     = 0(%rsp)  <- rsp
```

返回地址位置正确给 1 分，两参数位置和次序正确给 1 分。第七个参数并不是入口的 `0(%rsp)`，这个位置已被 `call` 写入返回地址。

### 4. 返回值与修改的寄存器（2 分）

返回 `7+8+1=16`，1 分。函数体修改 `%rax`，`ret` 还会推进 `%rsp` 并改变控制流；它没有改写一般被调用者保存寄存器，按正常返回恢复调用者栈位置，1 分。允许把 `%rip` 列为控制转移时改变的指令指针，不强求列出。两条 `addq` 还会更新条件码；这是另一个处理器状态变化，不属于破坏被调用者保存的通用寄存器。

### 5. 回收参数空间（1 分）

`ret` 只弹出返回地址，不替调用者回收两个栈参数。返回后 `%rsp=0x3ff0`，加 16 后恢复成 `0x4000`。原因和结果各 0.5 分。

### 6. 交换 push 顺序（2 分）

交换后，第七参数位置读到 8，第八参数位置读到 7，违反了原本希望传入 `(...,7,8)` 的次序，1 分。本函数恰好把两数相加，加法交换后结果不变；如果函数算第七参数减第八参数，结果就会改变。因此这次输出没变不能证明传参顺序正确，1 分。
