# 第 1 讲练习答案：整数与汇编入门

对应[第 1 讲正文](../第1讲-整数与汇编入门.md)。这是教学练习解析，不是用户作答记录。首次独立完成 D1-P1—P7 后再核对；途中得到提示的作答点不计入首次独立正确率，但可以记录修正后的理解。

必做题合计 **25 分，20 分达到 80% 门槛**。各题为 P1 4 分、P2 3 分、P3 3 分、P4 4 分、P5 3 分、P6 3 分、P7 5 分。以下评分是本讲训练口径，不是任何原卷的官方评分。小问含多个要求时按列明评分点给分，不用“整题全对才得分”。

## D1-P1：两种解释与字节序（4 分）

**1. 二进制是 `1011 0110`。（1 分）**

一位十六进制换四位：B 对应 1011，6 对应 0110。此时只是在写位模式，还没决定正负。

**2. 无符号为 182，8 位补码为 −74。（各 1 分）**

无符号值：11×16+6=182。最高位是 1，按补码解释需减去 2⁸，得到 182−256=−74。也可按负权重算 `−128+32+16+4+2=−74`。

**3. 小端内存排列如下。（1 分）**

| 地址 | 0x5000 | 0x5001 | 0x5002 | 0x5003 |
|---|---|---|---|---|
| 字节内容 | D4 | C3 | A2 | 81 |

先把完整数拆成 81、A2、C3、D4 四个字节；小端将最低有效字节 D4 放到最低地址。不翻转单个字节内的位。四格均正确得 1 分；若整体方向反了，回看正文图 D1-F3。

## D1-P2：位运算、逻辑与短路（3 分）

**1. `a & b=0`，`a && b=1`。（各 0.5 分）**

```text
a = 0x28 = 0010 1000
b = 0x14 = 0001 0100
按位与       0000 0000
```

两个数中为 1 的位没有重合，所以按位与为 0。但 a、b 都不是零，分别当逻辑真，因此逻辑与为 1。

**2. 不执行除法，r=0。（各 0.5 分）**

`z!=0` 为假；`&&` 在左边为假时短路，不再计算 `18/z>1`。不能说“先除零，再因为左边为假所以没事”；这里安全的原因是右边根本没有被求值。

**3. 可写 `x & ~0xFu`，也可写 `x & 0xFFFFFFF0u`。（1 分）**

低四位的掩码为 1111，取反后为低四位 0、其余位 1。与 0 会清零，与 1 会保留。本题 unsigned int 是 32 位，因此两个表达式等价。

## D1-P3：整数提升与公共类型（3 分）

**1. a 的表示为 `0xFFFFFFEE`。（1 分）**

−18 的 8 位补码是 256−18=238，即 0xEE。c 扩成 int 时保留数值 −18，所以复制符号位到高位。只写 `0x000000EE` 会把它变成正数 238。

**2. 在 int 中相加，t=270。（类型和结果各 0.5 分）**

unsigned char 的所有值都能用 32 位 int 表示，所以 p、q 先提升为 int；计算 240+30=270；目标 t 又是 int，不会发生 8 位截断。这题没有“保留低 8 位”的步骤。

**3. `-3 < 2U` 为假；`-3L < 2U` 为真。（每个判断及其对应类型合计 0.5 分）**

- 第一式：int 与 unsigned int 同等级，公共类型是 unsigned int。−3 转成 2³²−3，这是大正数，小于 2 不成立。
- 第二式：本环境 long 是有符号 64 位，能够容纳所有 unsigned int，公共类型是 long。因此比较的是 −3L 和 2L，小于成立。

若只写“因为有 U 所以都转无符号”，第二问会出错。要先看类型等级与能否容纳。

## D1-P4：右移、bias 与语言规则（4 分）

**1. 逻辑右移为 `0010 1011`；算术右移为 `1110 1011`。（各 0.5 分）**

两种操作都丢弃最右两位。逻辑右移在左边补两个 0；算术右移复制原最高位 1，所以补两个 1。

**2. 除法为 −3，算术右移为 −4；bias=7，修正后为 −3。（四项各 0.5 分）**

数学商 −25/8=−3.125。C 整数除法向零截断，因此得到 −3；本题算术右移向下取整，得到 −4。用 2³−1=7 修正：`−25+7=−18`，`−18` 算术右移 3 位就是 `floor(−18/8)=−3`。

不要把 bias 加到正数上：例如 9/8 应得 1，若对正数也加 7，则 16>>3 会错成 2。这个偏置是专为负数两种舍入方向不同而加入的。

**3. 不能保证。该 C 表达式有未定义行为。（1 分）**

1U 的类型是 32 位 unsigned int，移位量 32 等于左操作数宽度。C 要求移位量非负且小于该宽度；本题违反条件。不能因为 x86 某条移位指令会处理计数低位，就宣布 C 表达式等于 1。答出“未定义行为”及宽度依据得分；只写“不是 1，而是 0”不得分。

## D1-P5：子寄存器（3 分）

三问都从原 rax=`0x89ABCDEFFEDCBA98` 出发，不顺次叠加。

| 小问 | 完整 rax | 解释 |
|---|---|---|
| 1 | `0x89ABCDEFFEDCBA11` | 只写低 8 位 al，其余 56 位保留 |
| 2 | `0x0000000076543210` | 写 eax 得到低 32 位，同时清高 32 位 |
| 3 | `0x00000000FFFFFF98` | 原 al=0x98，符号扩展到 eax 得 0xFFFFFF98；写 eax 又清 rax 高位 |

每项 1 分。第三问不能写 `0xFFFFFFFFFFFFFF98`，那是扩展到 64 位的 `movsbq` 才产生的结果；本题 `movsbl` 目标为 32 位。

如果第三题做错，先单独写 eax 的值，再执行“写 eax 清高位”这一步，不要凭“有符号”三个字一次把 64 位都补成 1。

## D1-P6：寻址与传送（3 分）

先算共同的地址表达式：

```text
0x10 + 0x200 + 3×8
= 0x10 + 0x200 + 0x18
= 0x228
```

| 小问 | rax 的值 | 是否读取数据内存 | 解释 |
|---|---|---|---|
| 1 | `0x228` | 否 | lea 只保存地址表达式的计算结果 |
| 2 | `0x8899` | 是 | movq 从 0x228 开始读取 8 字节 |
| 3 | `0x228` | 否 | `$` 表示立即数，直接复制常量 |

每问结果 0.5 分、是否访存 0.5 分。第一行与第三行结果一样，但来源不同：一个通过算术计算得到，一个来自指令里的立即数。这些回答均不统计 CPU 为执行程序而取指令的访问。

## D1-P7：五行状态追踪（5 分）

用 `M32[A]` 表示从地址 A 开始的 4 字节位模式。本题初始 `M32[0x1008]=0x00000007`，`M32[0x100C]=0xFFFFFFFE`。

| 行 | 源值/地址计算 | 该行执行后的改变 | 内存行为 |
|---|---|---|---|
| 1 | 0x1000+2×4=0x1008 | rdx=`0x1008` | lea 不读写数据内存 |
| 2 | 读 M32[0x1008]，值为 0x00000007 | rax=`0x0000000000000007` | 读 4 字节，内存不变 |
| 3 | 地址 rdx+4=0x100C；源位模式 0xFFFFFFFE；原 eax=7 | rax=`0x0000000000000005` | 读 4 字节，内存不变 |
| 4 | 源 eax=5；目的地址 rdx=0x1008 | M32[0x1008]=`0x00000005` | 写 4 字节；寄存器不变 |
| 5 | 读 M32[0x100C]，按 32 位补码为 −2 | rcx=`0xFFFFFFFFFFFFFFFE` | 读 4 字节；内存不变 |

第三行是 32 位机器加法：`0x00000007 + 0xFFFFFFFE = 0x1_00000005`，只保存低 32 位 0x00000005；写 eax 同时清 rax 高位。也可按补码理解成 7+(−2)=5。不能把进位产生的第 33 位留在 rax 中。

第四行只覆盖 0x1008—0x100B，不会改动 0x100C—0x100F。因此第五行仍然读到原来的 −2；符号扩展的目标直接是 64 位 rcx，高位全补 1。rdi、rsi 和 rdx 在相应行之外均保持不变。

**评分：每行 1 分，其中源/有效地址 0.5 分，目的的值及读写方向 0.5 分。** 第 2、3 行若只报告 eax 而忽略要求的完整 rax，结果部分最多得 0.25 分；第 4 行若只写“结果为 5”却没说明写到内存，结果部分不得分。最终数值碰巧正确，不能补回错误的内存读写方向。

## D1-A1：可选边界题

不纳入必做 25 分。另设 3 个自检评分点，每小问 1 分，结果与原因都正确才通过该点。

**1. `-INT_MIN` 不能保证得到正数。**

INT_MIN=−2³¹，对它取数学相反数是 2³¹，大于 INT_MAX=2³¹−1。结果不能用 int 表示，C 有符号运算溢出，属于未定义行为。若另一个题明确要求 32 位机器取负，则其位模式会保持最小负数的模式；这不是该 C 表达式的普遍语言保证。

**2. `a+1U` 为 0，但 `INT_MAX+1` 无可靠的 C 数值结果。**

a 是 unsigned int：`(2³²−1)+1=2³²`，对 2³² 取模为 0，属于明确规定的无符号运算。INT_MAX+1 在 int 中超过上界，属于有符号溢出。两者碰巧可能在某段低级机器代码中用相同加法器，也不能抹平 C 语义区别。

**3. `a+1` 是 int 类型的 256；赋给 unsigned char b 后 b=0。**

unsigned char 的 a 先提升为 int，再和 int 常量 1 相加；256 没超过 int 范围。赋值给 unsigned char 才转换到 8 位无符号，按模 256 得到 0。顺序必须是“提升 → 加法 → 转窄”，不是“8 位加法自然变零”。

完成检查：能分别指出未定义行为、无符号取模与整数提升三个不同原因，才算掌握这道边界题。

## D1-A2：可选对齐题

改编来源：2025 期末第一题第 3 小题，PDF 第 2 页；移位量由 5 改为 3。本题不纳入必做 25 分。另设 3 个自检评分点：等价掩码 1 分、用商余数说明大小和差值范围 1 分、数值验证及倍数情形 1 分。

**1. 等价表达式为 `x & ~7U`，也可写 `x & 0xFFFFFFF8U`。**

右移 3 位丢掉低 3 位；再左移 3 位让保留下来的位回到原位置，但最右边只能补 0。两步合起来就是清低 3 位。

**2. y≤x，且 0≤x−y≤7。**

把无符号整数写成 `x=8q+r`，其中 0≤r≤7。右移得到 q，再左移得到 8q，因此 y=8q=x−r。删掉的 r 非负，所以 y≤x；差恰好是 r，因此最多是 7。

这里的左移不会额外丢失本来应保留的有效位：第一步右移已把高端空出三位，第二步只是把这些保留下来的位移回去。不能单凭“任何左移都可能溢出”而拒绝分析这个组合。

**3. x=77 时 y=72，差为 5；x 为 8 的倍数时 y=x。**

77=8×9+5；右移得 9，左移得 72。8 的倍数余数 r=0，即低 3 位本来全为 0，清零不改变它。这就是“向下对齐到 8 的倍数”的位操作含义。
