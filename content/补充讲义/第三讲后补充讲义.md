## Q022：什么时候走default，为什么索引要减10、还原case又要加10？

- 提问日期：2026-10-09（Asia/Shanghai）。
- 用户原始问题：

> 表有范围，进入前通常要检查索引。例如 `cmpq $3,%rdi; ja .Ldefault` 按无符号解释检查索引是否大于 3。若原始有符号 `x` 为负数，其位模式按无符号看是一个很大的数，也会去默认分支。因此这一条无符号跳转可以同时排除 `x<0` 与 `x>3`。若有效值从 10 开始，编译器还可能先算 `x-10`，让表从索引零开始。要恢复 `case` 值，必须把这个平移量加回来。
>
> 这一段中我能理解，这个条件下 x 小于 0 和 x 大于 3 都成立，但什么时候都取默认分值？然后后面那个有效值从 10 开始，x 减 10 就完全看不懂了

- 用户指定位置：复习第3讲2.1「跳转表里面存的是去哪里，不是计算结果」。
- 出处：已核对主讲义该段、相邻0～3跳表与本讲x86-64/AT&T前提。此处为助手教学示例；原课件与教材精确页码待核实。
- 解答性质：助手补充。先假设case连续且完整为0～3，再独立假设case为10～13；两者不是同一个switch中的连续两次检查。索引偏移按64位机器运算解释。

### 1. 是x<0或x>3，不是两者同时成立

假设switch只有case 0、1、2、3，则x取这四个值时进入对应case，其他值没有匹配项，进入default。

| x | 选择的入口 |
|---|---|
| −1 | default |
| 0 | case 0 |
| 1 | case 1 |
| 2 | case 2 |
| 3 | case 3 |
| 4 | default |

“同时排除两端”表示同一检查能处理两类不合法输入，不是某个x同时小于0又大于3。**逻辑是x<0或x>3，只要有一项成立就走default。**

default是默认分支的代码入口，不是叫作“默认值”的某个固定数。它可以返回一个值、修改变量，或做其他操作，具体看代码。没有default标签的C switch在没有case匹配时会跳过整个switch主体；不能假定任何switch都有固定默认返回值。本例明确设有.Ldefault路径。

### 2. ja不成立时，会继续查表

```asm
cmpq $3, %rdi       # rdi保存原始x；比较x与3
ja .Ldefault       # 无符号x>3时跳走
# 不跳走时，继续执行后面的查表跳转
```

ja表示无符号大于，不含等于。x=3依然合法；它不是jmp那样的无条件跳转。

- x=2，按无符号仍为2，不大于3，不跳default。
- x=4，按无符号为4，大于3，跳default。
- x=−1，64位全1，按无符号读为2⁶⁴−1，大于3，跳default。

所有64位有符号负数的位模式按无符号读都很大，所以也都被拒绝。合法的0～3通过检查后才读取跳转表，避免用负索引或越界索引访问表。

### 3. 为什么case从10开始就先减10？

现在换一个独立例子：只有case 10、11、12、13。四项紧凑跳转表依然从索引0开始：

```text
表[0] → case 10的代码
表[1] → case 11的代码
表[2] → case 12的代码
表[3] → case 13的代码
```

原始输入值是case编号，表索引是它在这张表里的位置，两者不再相同。计算 `索引=x−10` 就把10、11、12、13分别对应到0、1、2、3。

像门牌号10～13的四间房，在名单里的编号可以是0～3；房间12对应名单索引2，门牌号本身没有改成2。

这避免为了从原始x直接索引而预留0～9那些前置表项。这里是在解释一种常见实现，不声称所有switch都必须使用跳转表或这种布局。

### 4. 这次检查索引，不是拿原始x直接和3比较

一个保留原始x的示意片段是：

```asm
leaq -10(%rdi), %rax     # rdi仍为x；rax保存x−10的低64位
cmpq $3, %rax           # 比较索引与3
ja .Ldefault           # 无符号索引>3则走默认分支
# 否则，用rax中的0～3索引查这张四项表
```

这里lea只是计算偏移，不读取rdi指向的内存。`.Ldefault`及实际跳表跳转由完整程序提供。该片段讨论机器定宽运算，不是在C中对任意有符号x无条件执行可能溢出的x−10。

| 原始x | 机器索引低64位的解释 | 结果 |
|---|---|---|
| 9 | 9−10为−1，对应全1；无符号值2⁶⁴−1 | 大于3，default |
| 10 | 0 | 表[0]→case 10 |
| 12 | 2 | 表[2]→case 12 |
| 13 | 3 | 表[3]→case 13 |
| 14 | 4 | 大于3，default |

不能减完10以后仍用原始x判断是否大于3，否则合法的10～13也都会被错误拒绝。

### 5. 还原case为什么要加10？

程序建立的对应关系为 `索引=x−10`，所以读汇编时反推 `原始case值=索引+10`。

```text
看到表[0] → 原来是case 10
看到表[2] → 原来是case 12
```

这里“加回来”指分析者恢复C case标签时的计算，不是要求程序跳转前必须额外执行加10。若汇编已将x原寄存器覆盖成索引，则追踪寄存器时也要标明其含义变化，不能继续当原始x用。

以上例子假设范围内每个case都存在。实际表若在范围中间缺少某个case，对应表项还可以指向default；通过边界检查表示索引没有越界，不一定保证对应的是独立case代码。

## Q023：rax、rdx为什么既是被除数的高低位，又是商和余数？

- 提问日期：2026-10-10（Asia/Shanghai）。
- 用户原始问题：

> `idivq divisor` 使用一个 128 位被除数，它由 `%rdx:%rax` 拼成：`%rdx` 是高 64 位，`%rax` 是低 64 位。商放 `%rax`，余数放 `%rdx`。这一块稍微有点乱，这个 RAX 和 RDX 既是商和余数，也是高和低位吗

- 用户指定位置：复习第3讲2.2「看见cqto和idivq，不要继续把rdx当原参数」。
- 出处：已核对主讲义2.2的说明、除法代码与本讲x86-64/AT&T前提；原课件与教材精确页码待核实。
- 解答性质：助手补充；17÷5为教学示例，讨论指令正常完成时的寄存器变化。

### 1. 同两个寄存器，执行前后用途不同

寄存器可以反复写入数据。idivq先读取旧值做除法，再把商和余数写回，覆盖旧值。

| 时刻 | %rdx里是什么 | %rax里是什么 |
|---|---|---|
| 执行idivq前：输入 | 被除数的高64位 | 被除数的低64位 |
| 执行idivq后：输出 | 余数 | 商 |

**“高位、低位”说的是输入；“商、余数”说的是输出。不是同一时刻各保存两份值。** 两个寄存器各自始终只有64位，拼接后才组成128位被除数。

`%rdx:%rax`中的冒号表示位串拼接，不是除号。写在前面的rdx提供较高的64位，后面的rax提供较低的64位。

### 2. 用17÷5看完整过程

```asm
movq $17, %rax    # 被除数17先放入rax
cqto             # 将rax符号扩展成rdx:rax；17为正，所以rdx=0
movq $5, %rcx     # 除数5放入rcx
idivq %rcx       # 用rdx:rax中的有符号被除数除以rcx
```

执行除法前：

```text
rdx（高64位）        rax（低64位）
     0                    17
      └── 拼成128位被除数17 ──┘

rcx = 5：除数
```

高64位全零并不表示“没有使用128位输入”，而是17用128位表示时，前面那些位都是零。

因为 `17 = 3 × 5 + 2`，正常执行idivq后：

```text
rax = 3    商，覆盖原来的17
rdx = 2    余数，覆盖原来的0
rcx = 5    除数保持不变
```

这时应分别读取商与余数，不再把rdx和rax拼起来当作原来的被除数。

### 3. 为什么指令只写一个除数？

`idivq %rcx`只显式写出除数，但指令规定了隐含输入和输出位置：

- 被除数固定从rdx:rax读取。
- 商固定写入rax。
- 余数固定写入rdx。

这是idivq的指令规则，不是“所有汇编指令都把rax当商、rdx当余数”。执行别的指令时，这两个寄存器可以保存其他数据。

cqto是之前的准备步骤，本身不做除法、不改变rax，只把rax的符号扩展到rdx：非负数时rdx全零，负数时rdx全一。因此原来若有参数保存在rdx，它在cqto时就已被覆盖，不能等除法完成后仍把rdx当原参数。若后面还需要原值，应提前另存。

## Q024：push/pop保存的是值还是地址？call转到f、ret返回分别在做什么？

- 提问日期：2026-10-10（Asia/Shanghai）。
- 用户原始问题（含引用表格）：

> | `pushq %rbx` | 先把 `%rsp` 减 8，再把原 `%rbx` 写到新的栈顶   |
> | ------------ | --------------------------------- |
> | `popq %rbx`  | 从当前栈顶读 8 字节到 `%rbx`，再把 `%rsp` 加 8 |
> | `call f`     | 将下一条指令的地址压栈，再转到 `f`               |
> | `ret`        | 从当前栈顶取返回地址并弹出，转到该地址继续             |
>
> 针对这个表格的前两行，把 RBX 写到新的栈顶和读取下来，是指把地址写进去或者读取下来吗？然后第三行压栈我能理解什么意思，转到 F 是什么意思？最后第四行没太理解

- 用户指定位置：复习第3讲3.1「栈是一片内存，rsp是地址，不是数据盒子」。
- 出处：已核对主讲义3.1指令表、3.2调用过程图及本讲x86-64/AT&T前提；原课件与教材精确页码待核实。
- 解答性质：助手补充。地址和数值为教学示例，假设栈内存可正常访问；讨论本讲普通64位调用与不带立即数的ret。

### 1. pushq %rbx：rsp决定写到哪里，rbx决定写什么

假设开始时 `%rbx=42`、`%rsp=0x1000`。执行 `pushq %rbx` 时：

1. `%rsp` 减8，变为 `0x0ff8`。
2. 将 `%rbx` 中的64位值42复制到从 `0x0ff8` 开始的8字节内存，即 `0x0ff8`～`0x0fff`。

```text
执行前：rbx = 42，rsp = 0x1000

执行后：
rbx = 42                原寄存器不变
rsp = 0x0ff8            保存新的栈顶地址
0x0ff8起的8字节 = 42    栈内存保存复制来的值
```

**地址0x0ff8是“放在哪里”，数值42是“放什么”。** 本例栈里写入42，并不是写入0x0ff8，更不是写入某个“rbx寄存器自身的内存地址”。

如果rbx原来保存的是一个指针，例如地址值0x2000，那么压入的就是这个地址值0x2000。pushq %rbx不会因为它看起来像地址，就自动读取0x2000处的内存。rbx中保存的64位值被直接复制。

### 2. popq %rbx：取回栈内存的内容，不是栈顶地址

接着上例，在中间没有改变栈顶的情况下执行 `popq %rbx`：

1. 由rsp找到0x0ff8，从那里读取8字节，得到42，写入rbx。
2. rsp加8，恢复为0x1000。

```text
读内存的位置：0x0ff8
从那里读出的值：42
写入rbx的值：42，而不是0x0ff8
```

如果中间曾把rbx改成99，而栈内保存的42没有变，那么pop之后rbx会从99恢复成42。这就是保存寄存器旧值、稍后恢复它的一种方法。

“弹出”不要求把原内存字节擦成零；它通过移动rsp回收这8字节栈空间，原来的字节可能暂时还在。

### 3. call f：“转到f”是开始执行函数f的代码

f是函数入口的名字，对应一个代码地址。下面两条是调用者中的连续指令：

```asm
call f                 # 先去执行f
movq %rax, %rbx         # f返回后从这里继续
```

执行call时，不会立即接着执行movq，而是先完成两件事：

1. 把**紧接在call后面的movq指令的地址**压栈，作为返回地址。栈顶减8，那里保存这个代码地址。
2. 把接下来执行的位置改为f的入口，从f的第一条指令开始执行。

因此，“转到f”说的是CPU改变执行代码的位置，不是把f的数据复制到某个寄存器。保存的返回地址也不是f入口地址，而是“f完成后，调用者要从哪里接着执行”。

### 4. ret：取出返回地址，并从那里继续执行

假设这是一个没有使用额外栈空间的简单函数：

```asm
f:
    movq $7, %rax       # 准备整数返回值7
    ret                # 回到调用者
```

f是代码标签，标记函数入口；这里返回值放在rax中。ret正常执行时：

1. 从当前rsp指向的栈内存读出8字节返回地址。
2. rsp加8，弹出这个地址。
3. 从读出的代码地址继续执行，也就是调用者中的 `movq %rax, %rbx`。

```text
调用者执行 call f
       ↓ 保存“call后那条movq”的地址
进入f，执行 movq $7, %rax
       ↓ rax = 7
执行 ret
       ↓ 取出之前保存的返回地址
回到调用者，执行 movq %rax, %rbx
       ↓ rbx = 7
```

这里要分别追踪两个东西：**返回地址决定回哪里执行；返回值7是函数算出的数据。** ret取出的是地址，不负责从栈顶读取整数返回值。本例ret不改变rax中的7。

若函数在中间push了别的数据，或减小rsp预留了局部空间，需要先恢复栈，使rsp重新指向返回地址，再执行ret。ret不会自动寻找“哪个栈槽里才是正确的返回地址”；它直接使用当前栈顶内容。

### 5. 对照四条指令的用途

| 指令 | 栈内保存或读取的内容 | 是否改变接下来执行的代码位置 |
|---|---|---|
| pushq %rbx | 保存rbx中的值，可能是整数，也可能是指针 | 正常情况下继续下一条指令 |
| popq %rbx | 将栈顶保存的值写入rbx | 正常情况下继续下一条指令 |
| call f | 保存call后面那条指令的地址 | 开始执行f |
| ret | 取出当前栈顶的返回地址 | 从取出的地址继续执行 |

## Q025：调用者保存、被调用者保存，究竟是谁保存、什么时候需要保存？

- 提问日期：2026-10-10（Asia/Shanghai）。
- 用户原始问题：

> **调用者保存**：`%rax,%rcx,%rdx,%rsi,%rdi,%r8,%r9,%r10,%r11`。被调用函数可以改它们。如果调用者返回后还需要其中旧值，应先保存到安全位置。
>
> - **被调用者保存**：`%rbx,%rbp,%r12,%r13,%r14,%r15`。函数可以使用它们，但若改了值，就要在返回前恢复成进入时的值。`%rsp` 也必须恢复到满足正常返回的位置，但通常不把它当一般临时寄存器列在这组里。
>
> “调用者保存”不等于调用前必须无条件保存全部寄存器；只保存后面还需要的值。“被调用者保存”也不等于每次进入函数必须压入全部六个；没修改就不需要保存。解释一下

- 用户指定位置：复习第3讲4.1「为什么有的值跨一次call就丢了」。
- 出处：已核对主讲义4.1、相邻栈操作与本讲System V AMD64调用约定；原课件与教材精确页码待核实。
- 解答性质：助手补充；以下A、B及数值10、99为教学示例，假定函数遵守本讲调用约定。

### 1. 先确定谁调用谁

假设函数A调用函数B，则A是调用者，B是被调用者。两个函数使用同一组寄存器，进入B时不会自动换一套。因此B改了寄存器，返回A后寄存器里可能已经不是原值。

“调用者保存”和“被调用者保存”是在分配保留旧值的责任。它们不是说寄存器属于哪个函数，也不是说call和ret会自动备份、恢复这些寄存器。

### 2. 调用者保存：A需要旧值，就由A提前保管

以rdi为例：

```text
A：rdi = 10
A：调用B
    B：把rdi改成99，用于自己的计算
    B：返回，无须把rdi恢复成10
A：此时rdi可能已是99，不能再依赖它保存10
```

如果A在B返回后还需要原来的10，A就先把它保存到自己分配的栈空间等安全位置，等B返回后再取出使用。如果后面不再需要10，就没有保存它的必要。

因此，“调用者保存”可以读成：**B允许改；A如果还要旧值，由A负责保留。** 不能读成每次call前必须把所有这类寄存器都压栈。

保存的是调用前需要保留的值。取回时也不要求一定写回原寄存器，只要后续计算能正确使用这个旧值即可。

### 3. 被调用者保存：B要改，就由B负责恢复

以rbx为例，进入B时rbx中原有10：

```text
进入B：rbx = 10
B先保存旧值10
B把rbx改成99，用于自己的计算
B返回前，把rbx恢复成10
回到A：rbx = 10
```

一个只展示B内部保存与恢复的片段是：

```asm
B:
    pushq %rbx         # 保存进入B时的旧值10
    movq $99, %rbx     # B可以临时修改它
    # ……其他计算……
    popq %rbx          # 恢复进入时的值10
    ret
```

push保存的是rbx中的值，pop把保存的值读回来；这些含义见Q024。这里B在中间没有进一步调用其他函数。

如果B始终不改变rbx，就不需要为它额外执行push/pop。如果B只修改rbx，没有修改rbp、r12～r15，就只需保证rbx被恢复，不必把另外五个也无条件保存。

**被调用者保存的要求是：返回时与进入时相同。中间可以改变。** 若修改这类寄存器，B不能擅自假设A不需要旧值而省略恢复。

### 4. 两种责任放在一起比较

| A调用B时 | rdi等调用者保存寄存器 | rbx等被调用者保存寄存器 |
|---|---|---|
| B能否修改 | 能，无须恢复 | 能，但返回前必须恢复 |
| 谁负责保留旧值 | A若后面需要，就提前保留 | B若要修改，就负责保留并恢复 |
| 可以不做额外保存的情况 | A在调用后不需要旧值 | B不改变该寄存器 |
| A能否在B返回后直接依赖旧值 | 不能仅凭约定保证 | 可以依赖遵守约定的B保留它 |

“可以修改”不表示B一定会修改调用者保存寄存器；只是A不能依赖B碰巧没有修改。

### 5. 安全位置与rsp的含义

将rdi复制到rcx通常不足以保证跨调用保存，因为rcx同样属于B可以改的寄存器。可以使用A妥善分配并保留的栈槽；若改用rbx保存，也要考虑A自身对它的调用者承担的恢复义务。

例如外层函数P调用A，A又调用B：A对B是调用者，对P又是被调用者。若A想使用rbx保存自己的数据，就应先保留P交给A时的rbx旧值，等A最终返回P前恢复。B则负责让A调用B时的rbx值在返回A时保持不变。

rsp保存栈顶地址。B若压过数据或分配过局部栈空间，应在ret前撤销这些额外占用，使rsp重新指向call存下的返回地址。随后ret再弹出该返回地址。不能误以为ret会替B清理任意多的局部空间。

## Q026：栈帧和rbp是什么？函数开头与leave/ret怎样改变栈？

- 提问日期：2026-10-10（Asia/Shanghai）。
- 用户原始问题：

> 这一部分完全没看懂

- 用户指定位置：复习第3讲4.2「栈帧与rbp：常见布局不是强制模板」。
- 出处：已核对主讲义4.2三条开头指令、结尾说明与相邻调用约定；原课件与教材精确页码待核实。
- 解答性质：助手补充。以下地址为教学示例，采用本讲x86-64/System V/AT&T语境，假定内存可正常访问；不假定所有函数均使用此布局。

### 1. 栈帧是一块区域，rbp可以保存固定的定位地址

先把栈帧理解成一次函数调用在栈上使用的区域，可以包含保存信息、局部数据和临时空间。栈帧不是新的寄存器，也不是一条指令。

在本节这种使用帧指针的布局中，rsp保存当前栈顶地址，rbp保存一个固定的基准地址。函数可以用“rbp加减多少”定位数据；rbp本身不装下整个栈帧。

假设A调用B。B刚开始执行时，call已经把返回A的地址放在栈顶；此时rbp仍是进入B之前的旧值。根据被调用者保存约定，B若要改rbp，就需要先保留旧值，以便返回前恢复。

### 2. 先跟着三条指令看地址变化

假设刚进入B时，rsp=0x1008，从0x1008开始的8字节内存保存返回A的地址。B的开头是：

```asm
pushq %rbp
movq %rsp, %rbp
subq $16, %rsp
```

第一条 `pushq %rbp`：rsp减8，从0x1008变为0x1000，并将rbp的旧值写到0x1000开始的8字节中。

**0x1000是保存旧值的位置，不代表旧rbp的值一定等于0x1000。** 例如旧rbp若是0x2000，这里保存的内容就是0x2000。

第二条 `movq %rsp, %rbp`：将rsp中当前的地址0x1000复制给rbp。现在两个寄存器都是0x1000。这条指令不访问栈内存，也没有再压栈；它让B建立自己的固定基准地址。

第三条 `subq $16, %rsp`：rsp减去十进制16，也就是十六进制0x10，变成0x0ff0。rbp仍为0x1000。在两者之间预留了16字节，供B按需使用。

```text
刚进入B：           rsp = 0x1008，rbp = 旧值
pushq %rbp之后：    rsp = 0x1000，rbp = 旧值
movq %rsp,%rbp后：  rsp = 0x1000，rbp = 0x1000
subq $16,%rsp后：   rsp = 0x0ff0，rbp = 0x1000
```

预留空间不等于写入数据。sub只改rsp，不会将这16字节清零，也不能仅凭预留16字节就推断C里一定有两个long变量。

### 3. 读懂这个栈布局和正负偏移

下面每行代表从所列地址开始的8字节；越往下地址越小。预留的16字节为了画图分成两行，并非断言一定存了两个变量。

| 内存起始地址 | 内容或用途 | 相对于rbp的位置 |
|---|---|---|
| 0x1008 | 返回A的代码地址 | 8(%rbp) |
| 0x1000 ← rbp | 保存的旧rbp值 | 0(%rbp) |
| 0x0ff8 | 预留空间的一半，可放局部数据 | -8(%rbp) |
| 0x0ff0 ← rsp | 预留空间的另一半，可放局部数据 | -16(%rbp) |

由于rbp=0x1000：

- `0(%rbp)`：访问0x1000处的内存；用8字节读取时得到保存的旧rbp值。
- `8(%rbp)`：访问0x1008处的内存；用8字节读取时得到返回地址。
- `-8(%rbp)`：访问0x0ff8处的内存，可在此放局部数据。
- `-16(%rbp)`：访问0x0ff0处的内存，也是预留空间。

例如B之后执行 `movq $42, -8(%rbp)`，就把42写进从0x0ff8开始的8字节中。此时这个局部数据的值是正数42，偏移却是负数−8。**负偏移只表示地址在基准地址下方，不表示变量值是负数。** 实际访问多少字节由指令宽度决定，偏移写法本身不规定数据宽度。

### 4. 为什么同时使用rsp和rbp？

在这种布局中，B的主体执行期间保持rbp=0x1000。rsp则可以因临时压栈、分配空间等操作变化。

例如再次push一个值，rsp会从0x0ff0变成0x0fe8，但rbp仍为0x1000。因此 `-8(%rbp)` 仍然定位到0x0ff8，访问原来的局部数据时不必随rsp的变化调整这个偏移。

rbp可以理解成固定的定位点，rsp表示当前栈顶。这只是采用帧指针时的一种安排，不是硬件禁止修改rbp。

### 5. 返回前怎样撤销这些操作？

对于这里建立的布局，若没有其他尚需恢复的寄存器，结尾可以是：

```asm
movq %rbp, %rsp
popq %rbp
ret
```

逐步执行：

| 步骤 | rsp的变化 | 其他效果 |
|---|---|---|
| movq %rbp,%rsp | 回到0x1000 | 回收预留的16字节，rbp仍为0x1000 |
| popq %rbp | 0x1000→0x1008 | 从0x1000读出旧rbp值，恢复到rbp |
| ret | 0x1008→0x1010 | 从0x1008读出返回地址，回到A继续执行 |

这里ret后的rsp=0x1010，正是A执行call之前的栈顶位置；call曾把它减8到B入口时的0x1008。

若旧rbp是0x2000，pop后rbp就恢复为0x2000，而rsp是0x1008；两个寄存器不需要相等。回收空间也不是擦除内存字节，只是改变栈顶位置。

前两条在本节常见布局下可由 `leave` 完成，因此常见结尾是：

```asm
leave     # 效果相当于movq %rbp,%rsp；popq %rbp
ret       # 取返回地址，回到调用者
```

**leave恢复栈和旧rbp，ret才转回调用者。** 若函数还保存了其他需要恢复的寄存器，也必须按实际布局妥善恢复，不能把leave当作自动恢复整个函数状态的指令。

### 6. “不是强制模板”和最后一段是什么意思？

简单函数可能只用寄存器计算，不需要额外局部栈空间。有些函数虽然使用栈，但可以直接用rsp加偏移定位，省略rbp帧指针。所以应先查看汇编有没有这三条建立栈帧的指令，不能看到任何函数就套用“0(%rbp)是旧rbp、8(%rbp)是返回地址”。

最后一段是在说明：局部变量不一定存在栈里。例如只计算 `x+1`，编译器可能一直用寄存器。若需要把某个局部变量的地址传给一个确实要通过该地址读写内存的函数，就需要提供真正的内存位置，栈是常见选择。

如果编译器已经把整个操作优化成别的等价计算，最终也可能不再需要那块内存。因此仅凭C代码写了 `&x` 仍不能断定最终汇编一定有栈槽；解题应跟踪实际指令。

### 追问1：rbp、rsp分别是干什么的？

- 提问日期：2026-10-10（Asia/Shanghai）。
- 用户原始问题：

> rbp rsp分别是干什么的

**rsp记录“当前栈顶在哪里”；rbp在本节使用帧指针的布局中，记录“以哪个固定位置来找本函数的数据”。** 这里两者保存的都是地址，不是直接装着所有局部数据。

| 寄存器 | 本节中的用途 | 变化情况 |
|---|---|---|
| %rsp | 指向当前栈顶；push/pop/call/ret通过它存取栈内存 | 随压栈、弹栈、分配或回收空间变化 |
| %rbp | 保存固定基准地址，通过偏移定位局部数据和保存的信息 | 建立帧指针后，在函数主体中通常保持不变，返回前恢复旧值 |

例如栈帧建立后：

```text
rbp = 0x1000    固定定位点
rsp = 0x0ff0    当前栈顶
```

再执行一次 `pushq %rax` 后：

```text
rbp = 0x1000    不变
rsp = 0x0fe8    减8，指向新栈顶
```

原来在0x0ff8的局部数据仍然能通过 `-8(%rbp)` 找到，因为0x1000−8始终为0x0ff8。这解释了固定基准地址的用途。

rsp的栈顶用途是上述栈指令规定的；用rbp作固定基准是程序的一种安排，不是所有函数都必须这样做。省略帧指针的函数可以直接用rsp加偏移定位；rbp也可用于其他计算，此时不能再把它当作固定栈帧地址。按本讲调用约定，修改rbp仍需在返回前恢复旧值。

### 追问2：保存A的rbp后给B使用，rsp指的是A的栈吗？

- 提问日期：2026-10-10（Asia/Shanghai）。
- 用户原始问题：

> 那我可以理解为：B 函数要使用 RBP，但 RBP 中还有之前 A 函数的东西，所以它需要先把 RBP 转移到 0x1008 这个位置，然后再把 B 函数占用的 RSP 复制到 RBP 上，防止 RBP 的数据丢失 那这个 RSP 指的这个栈是原函数 A 的栈吗

“先保存A的旧rbp，再让rbp供B使用”这个顺序正确。需要纠正保存位置：本例旧rbp保存到0x1000，而0x1008已经保存返回A的地址。保存的是寄存器中原来的值，不是把寄存器本身搬到内存里。

按时间顺序看：

| 时刻或指令 | rsp | rbp | 栈内存的变化 |
|---|---|---|---|
| A执行call B前 | 0x1010 | A的旧值 | A原有数据仍保留 |
| 刚进入B | 0x1008 | A的旧值 | call在0x1008处存了返回地址 |
| pushq %rbp | 0x1000 | 仍为A的旧值 | 将旧rbp值复制到0x1000处 |
| movq %rsp,%rbp | 0x1000 | 0x1000 | 没有读写栈内存；只复制当前栈顶地址 |
| subq $16,%rsp | 0x0ff0 | 0x1000 | 在较低地址预留16字节，未初始化 |

因此，防止旧rbp丢失的是第一条push做出的内存备份；第二条mov则覆盖rbp，让它成为B的固定定位点。B返回前可以从保存位置取回A的旧值。

本例普通函数调用中，A和B使用同一条线程栈，不是调用B时新建一片独立的栈。A暂停执行，但它仍在等待B返回，因此A原来的栈数据还要保留。B从当前栈顶继续向低地址使用空间。

```text
高地址
┌───────────────────────────┐
│ A原来正在使用的栈区域      │
├───────────────────────────┤
│ 返回A的地址               │ 0x1008
├───────────────────────────┤
│ 保存的A的旧rbp值          │ 0x1000 ← B的rbp
├───────────────────────────┤
│ B预留的局部空间           │
│                          │ 0x0ff0 ← B分配16字节后的rsp
└───────────────────────────┘
低地址
```

这里说“A的栈帧”“B的栈帧”，是同一条栈中与不同函数调用相关的区域。rsp始终记录当前栈顶地址，不是A、B各有一份同时工作的rsp寄存器；rbp同样在调用过程中被保存、重新设定、再恢复。

B返回时收回自己的空间并恢复旧rbp，ret取出返回地址并使rsp回到本例A调用前的0x1010，A便能继续执行。本次追问更正的是具体地址与栈的关系，不能据此认定整节已经掌握。
