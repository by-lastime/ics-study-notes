## Q027：结构体对齐在讲什么？为什么成员合计15字节，结构体却占24字节？

- 提问日期：2026-10-11（Asia/Shanghai）。
- 用户原始问题：

> 这一部分是在讲什么

- 用户指定位置：复习第4讲第2节「结构体要满足成员与整体的对齐」。
- 出处：已核对主讲义第2节、例D4-E2的结构体与图4-3、字段反推示例。主讲义标注例题来自2025期末无答案版第一大题第4题、PDF第3页；本次未重新核对原卷，印刷页码待核实。
- 解答性质：助手补充。沿用本课程x86-64/Linux/System V默认自然对齐模型，不使用packed或显式提高对齐要求等特殊布局。

### 1. 这一节在计算内存里的位置和总空间

结构体把几个成员组合成一个整体。这一节关心：每个成员放在哪个位置、哪些地方留空、整个对象占多少字节。

```c
struct S {
    char c;
    int i;
    short s;
    double d;
};
```

四个成员在本课程平台下分别占1、4、2、8字节，合计15字节。但这个结构体实际占24字节，因为中间有9字节填充。

### 2. 对齐是对存放地址的要求

int按4字节对齐，意思是它的起始地址应是4的倍数，不是它保存的数值必须是4的倍数。

| 类型 | 本课程大小 | 默认对齐要求 |
|---|---|---|
| char | 1字节 | 起始地址是1的倍数，即任意字节位置 |
| short | 2字节 | 起始地址是2的倍数 |
| int / float | 4字节 | 起始地址是4的倍数 |
| long / double / 指针 | 8字节 | 起始地址是8的倍数 |

这里是课程采用的平台布局约定，不是对所有C实现的统一大小保证，也不是说x86在任何情况下都不能访问不对齐的地址。

手算时把结构体开头称作偏移0。偏移表示距离开头多少字节，实际地址等于结构体起始地址加偏移。在本例中，结构体起始地址本身已满足8字节对齐，所以用偏移是否为相应倍数来判断即可。0也是2、4、8的倍数。

### 3. 按声明顺序摆放成员

先放c：从偏移0开始，占1字节，下一个可用偏移为1。

再放i：偏移1不是4的倍数，向后找到4。因此偏移1、2、3留空，i占偏移4～7，下一个可用偏移为8。

再放s：8已经是2的倍数，直接放在偏移8～9，下一个可用偏移为10。

最后放d：10不是8的倍数，向后找到16。偏移10～15留空，d占偏移16～23，下一个可用偏移为24。

| 字节偏移范围 | 用途 | 占用字节数 |
|---|---|---|
| 0 | c | 1 |
| 1～3 | 填充 | 3 |
| 4～7 | i | 4 |
| 8～9 | s | 2 |
| 10～15 | 填充 | 6 |
| 16～23 | d | 8 |

因此实际成员占15字节，填充占3+6=9字节，合计24字节。偏移从0数到23，表示24字节，不是23字节。

填充没有对应的结构体成员，不是隐藏变量，也不保证内容为零。sizeof计算整个对象的大小，包含填充，所以本例 `sizeof(struct S)=24`。

### 4. 成员放完后为什么还要检查整体大小？

在本节默认模型中，结构体的对齐要求是各成员对齐要求的最大值，本例为8。成员放完之后，还要将总大小向上凑成8的倍数。24已经符合，因此原例不需要末尾填充。

这条规则是为了让结构体数组中后面的元素也正确对齐。例如讲义将声明顺序改为：

```c
struct T {
    double d;
    int i;
    short s;
    char c;
};
```

新布局中d占0～7，i占8～11，s占12～13，c占14，成员共占15字节。末尾还要补1字节，即偏移15，最终大小为16。

若数组 `struct T a[2]` 每个元素占16字节，a[1]从数组起点后16字节开始，里面第一个double仍满足8字节对齐。假如错误地按15字节一个元素，a[1]中的double从偏移15开始，就无法满足该要求。

修改声明顺序会改变成员偏移和填充量；编译器不能擅自把原struct S的成员重排成struct T的顺序。两者具有相同的成员类型组合，但不是相同的布局。

### 5. 手算时只需逐个找最近的合法位置

每次放成员前，先看当前偏移是否符合它的对齐要求：符合就直接放，不符合就向后找到最近的倍数；放好后再加上成员大小。全部放完后，再按结构体整体要求调整总大小。

例如当前偏移10、要求8字节对齐，下一个合法位置就是16；当前偏移8、要求2字节对齐，8本身已合法，不要再移到10。

讲义的 `align(x,K)=ceil(x/K)*K` 就是把这件事写成公式：x是当前偏移，K是对齐要求，ceil表示向上取整。初学时可以直接找倍数，不必先背位运算表达式。

### 6. 最后一段是反过来：由偏移推布局

`movl 12(%rdi),%eax` 表示从rdi指向的位置后12字节处读取4字节。它告诉你访问位置和宽度，但不单凭这一条就保证那里一定是某个int字段。

主讲义的另一个例子是：

```c
struct R { char tag; int a[N]; long total; };
```

tag位于偏移0，int数组a从偏移4开始。如果题目说total从偏移24开始，有两种可能：

- N=4：a占4～19，偏移20～23为填充，total从24开始。
- N=5：a占4～23，不需要额外填充，total同样从24开始。

因此不能把24−4=20字节全部认作数组数据，再除以4就断言N必为5。这里提醒的是：偏移之间可能包含填充，反推时要保留所有符合约束的可能。

## Q028：联合这一节在讲什么？为什么写b的字节，也会改变w？

- 提问日期：2026-10-11（Asia/Shanghai）。
- 用户原始问题：

> 这个章节又在说什么

- 用户指定位置：复习第4讲第3节「联合是共享同一片字节」。
- 出处：已核对主讲义第3节、助手补充例D4-E3及图4-4；本问不新增教材或原卷页码引用。
- 解答性质：助手补充。按课程x86-64/Linux/System V、8位字节、4字节unsigned int、小端及默认自然对齐前提分析联合例子；不使用packed等特殊布局。

### 1. 联合让不同成员共用同一块内存

union叫联合或联合体。讲义中的定义是：

```c
union U {
    unsigned char b[4];
    unsigned int w;
};
```

b是一个数组，包含4个unsigned char元素，每个占1字节；w是一个占4字节的无符号整数。U是这个联合类型的名字；再写 `union U u;` 才声明一个名叫u的变量，`u.b[0]` 表示它的b数组的第0个元素。

在本例中，b和w使用同一块4字节内存：b按4个小格子访问，w把4个格子合起来作为一个整数访问。它们不是两份独立数据。

### 2. 对比结构体：分开放与重叠放

如果把定义里的union改成struct，b和w各有自己的空间，本课程布局下总共8字节：

```text
struct：偏移0～3放b，偏移4～7放w
[ b[0] ][ b[1] ][ b[2] ][ b[3] ][ w的四个字节 ]
```

联合则让它们从同一起点开始：

```text
字节偏移：     0       1       2       3
按b访问：   [ b[0] ][ b[1] ][ b[2] ][ b[3] ]
按w访问：   [         w的四个字节          ]
```

图中两行是同一块内存的两种读法，不是上下两块内存。联合成员都从偏移0开始，所以本例sizeof为4。

一般计算联合大小时，要先容纳最大的成员，再满足整体对齐。例如默认布局下 `union V { char a[9]; double d; };` 最大成员占9字节，整体要求8字节对齐，因此大小向上凑到16字节。不能把所有联合大小都简单写成最大成员的大小。

### 3. 逐字节写入，再把整块作为整数读取

```c
union U u;
u.b[0] = 0x11;
u.b[1] = 0x22;
u.b[2] = 0x33;
u.b[3] = 0x44;
```

这四次写入完成后，内存按地址从低到高排列如下：

| 地址 | 通过数组访问的名字 | 字节内容 |
|---|---|---|
| B | u.b[0] | 0x11 |
| B+1 | u.b[1] | 0x22 |
| B+2 | u.b[2] | 0x33 |
| B+3 | u.b[3] | 0x44 |

读u.w时，就是把这四个字节作为一个unsigned int读取。没有额外的复制操作，也没有另一份单独的w存储空间。

### 4. 小端为什么得到0x44332211？

小端规定低地址存整数的低位字节。B处的0x11是最低8位；B+3处的0x44是最高8位。每个字节对应两位十六进制数字，因此把整数按高位在左的通常写法写出来，是：

```text
整数从高位到低位：  44    33    22    11
来自：            b[3]  b[2]  b[1]  b[0]
结果：            0x44332211
```

等价地，数值是 `0x44 × 2^24 + 0x33 × 2^16 + 0x22 × 2^8 + 0x11`。

内存中的字节没有倒过来，变的是展示顺序：地址表按低地址到高地址排列，整数的十六进制写法则把高位写在左边。如果题目指定大端，同样的四个内存字节读成w就会是0x11223344。

### 5. 修改一个成员，为什么会影响另一个？

在前面写入之后继续执行：

```c
u.b[0] = 0xAA;
```

内存从低地址到高地址变为AA、22、33、44；按本题小端前提，u.w就从0x44332211变为0x443322AA。只改了一个数组元素，却改变了w读到的整数，因为它们访问的是重叠的字节。

同样，若随后写 `u.w = 0;`，整个4字节整数变成零，其四个字节也都是零，因此u.b[0]到u.b[3]均读到0。不能指望b和w各自保留互不相关的旧值。

### 6. 最后一句在区分位重解释与数值转换

数值转换要根据原数值计算目标类型的数值。例如 `(int)1.5f` 得到1，去掉小数部分。

位重解释保留原来的位模式，改用另一种编码规则读取。例如IEEE binary32的1.5f位模式是0x3FC00000；若将这32位按无符号整数解释，得到1069547520，并不是1。

这里的联合例题按课程指定的C实现与整数表示前提分析。不要因此认为任意指针强制转换后都能合法地跨类型读取；查看对象的字节可用unsigned char指针，复制对象位模式可用memcpy。

## Q029：怎样读栈图、数结束零，为什么7、8、24个字符的结果不同？

- 提问日期：2026-10-11（Asia/Shanghai）。
- 用户原始问题：

> 这一部分没看懂，解释一下

- 用户指定位置：复习第4讲「例D4-E5 根据给定栈图数越界长度」。
- 出处：已核对主讲义第5节、助手补充例D4-E5的布局与字符串复制前提。本次按该例解释，不新增教材或原卷页码引用。
- 解答性质：助手补充。以下只分析题给机器布局，不把它当作所有编译器的固定栈布局，也不执行越界代码。

### 1. 这道题是在数：写入的每个字节落到哪里？

buf是一个8字节数组。复制操作从它的起点B开始，逐字节向地址增加的方向写入。如果复制不检查长度，数组空间用完后，写入仍可能继续覆盖旁边的内存。

把题目原本高地址在上的图改成从左到右地址增加，布局如下：

```text
偏移：  0～7       8～15       16～23          24～31
用途：  buf[8]    填充        保存的rbp       保存的返回地址
写入：  从B开始，一字节一字节向右写 →
```

B是地址，不是数组里保存的数值。B+7是起点后7字节的位置。数组下标从0开始，因此8字节的合法位置为B到B+7；B+8已经是第9个位置。

填充不是buf的一部分，写到填充也算越界。栈分配空间时通常向低地址增长，与这次复制按buf[0]、buf[1]等向高地址写入并不矛盾：这是两种不同操作。

### 2. 字符串结束零也占一个位置

C字符串用值为零的字节 '\0' 表示结束。它不是普通字符'0'，也不是反斜杠和0两个字符。

题目明确说：先写n个非零字符，再追加一个结束零。所以：

- 普通字符写到偏移0～n−1（n大于0时）。
- 结束零写到偏移n，即地址B+n。
- 总共写n+1字节。

例如7个普通字符：

```text
偏移： 0  1  2  3  4  5  6   7
内容： A  B  C  D  E  F  G  '\0'
```

总共8字节，全部在buf内。按题目这种复制方式，最多只能放7个普通字符。

### 3. 为什么n=8就已经越界？

```text
偏移： 0  1  2  3  4  5  6  7 | 8
内容： A  B  C  D  E  F  G  H | '\0'
       数组的8个合法位置         数组外
```

8个普通字符占满buf，结束零只能写到B+8，落在图中的填充区域。第一次越界已经发生，不需要等到覆盖rbp或返回地址才算越界。

### 4. 为什么n=24碰到返回地址？

24个普通字符从偏移0写到23，其中：

| 偏移 | 原本用途 | 此时写入情况 |
|---|---|---|
| 0～7 | buf | 前8个普通字符 |
| 8～15 | 填充 | 接下来的8个普通字符，已越界 |
| 16～23 | 保存的rbp | 最后8个普通字符，已越界 |
| 24 | 保存的返回地址的首字节 | 结束零，已越界 |

因此结束零正好写到B+24。这里不是覆盖了完整8字节返回地址，而是写入其第一个字节。若该字节原来已经为零，这次写零可能不改变它的值；但访问仍然越界，而且此前也已经写到了保存的rbp区域。

### 5. 返回地址被改动，为什么会影响执行？

call保存返回地址，记录被调用函数结束后应该从哪里继续。正常返回时，ret从相应栈位置取出地址并转去执行。保存的地址若被改坏，就可能造成错误跳转或崩溃；具体结果还受栈恢复过程与防护机制影响，不能保证每次都出现同一种现象。

这道题的计算结论是：n=7不越界；n=8首次越界；n=24使结束零写到返回地址首字节。题给机器模型帮助分析可能覆盖的位置；在C语言层面，越界属于未定义行为，不能用“这次没崩溃”证明代码合法。

## Q030：长度检查、ASLR、NX和canary分别在防什么？

- 提问日期：2026-10-11（Asia/Shanghai）。
- 用户原始问题：

> 这一部分也没看懂

- 用户指定位置：复习第4讲「防护方法分别改变了什么」。本问与D4-E5的问题在同一条消息提出，例题解释见Q029。
- 出处：已核对主讲义第5节防护表及紧随其后的接口、canary与NX说明；本次不新增教材或原卷页码引用。
- 解答性质：助手补充，解释各机制的作用与局限，不声称一种机制能消除所有内存错误。

### 1. 四项机制处理的是不同环节

接着D4-E5来看：数组只有8字节，不检查长度的复制却可能继续写到外面。防护可以从不同环节介入：避免越界写入、增加地址预测难度、禁止执行某些页的字节、检查栈中的保护值是否被破坏。

### 2. 长度检查：别让数据写出数组

在这道题中，检查的应是“普通字符数+一个结束零”是否小于等于8。7个普通字符能放下；8个普通字符再加结束零就不行。程序需要根据需求拒绝过长输入，或正确限制复制长度并保证结束零等条件。

这直接针对越界的原因。接口名含有n不代表自动安全，传入的容量也必须正确。例如fgets在成功读取、容量为8的通常使用下最多存7个输入字符，再追加结束零；若读到了换行，它也占字符位置。还需检查读取是否成功、是否留有未读完的输入。strncpy在源字符串过长等情况下不会自动追加结束零，不能只看名字判断安全。

### 3. ASLR：让相关区域的实际地址更难预测

ASLR是地址空间布局随机化。可以想象同一类对象这次位于某个地址，下次运行所在区域可能换到另一个地址；哪些区域随机化依赖系统和程序配置。

它增加预测相关地址的困难，但不让buf变大，也不替程序检查长度。在D4-E5给定布局下，即使B改变，buf仍只有B到B+7这8字节，结束零写到B+8仍越界；题给的相对偏移不会仅因基址随机化自动消失。

### 4. NX：数据能存放，不代表能当指令执行

CPU执行机器指令时，需要从某个地址取指令字节。NX表示不可执行：若该内存页没有执行权限，CPU不能从那里执行指令。

因此栈可以正常保存局部变量和返回地址，却不允许直接执行栈里的字节。NX不会阻止往栈写数据，也不会阻止越界写入本身。程序原有的代码页仍然需要可执行，因而NX也不能单独阻止利用已有代码的返回链；这就是后面ROP一节与本表的联系。

NX依赖处理器能力与操作系统配置配合。“需要硬件支持”不等于“当前机器必须更换CPU”；现代题设若已有这种支持，启用保护未必需要新硬件。

### 5. Canary：返回前检查一个保护值有没有被改

栈canary是编译器在受保护函数栈帧中安排的保护值。可把它理解成一个检查标记：进入函数时保存，退出时核对是否仍与预期相同。若连续越界写入经过它并改变其内容，检查就可能发现异常，通常会终止程序而非继续正常返回。

它检查的是“相等还是不相等”，不是值是否变大。例如一个简化的标记原来为某值，后来变小了，也同样属于变化。

canary的具体大小和位置依实现而定；D4-E5原图没有给出canary，不能擅自往该图加入保护槽并沿用原偏移计算。canary只能发现被该检查捕获的破坏，并不能发现所有内存错误，也不能自动把已经改坏的数据恢复。

### 6. 对照记忆

| 防护 | 主要问题 | 不代表什么 |
|---|---|---|
| 长度检查与正确使用有界接口 | 这次写入能否放进对象？ | 函数名有n就自动安全 |
| ASLR | 相关地址是否容易预测？ | 越界不再发生 |
| NX | 这个内存页是否允许执行指令？ | 不能写坏数据，或已有代码不能被重新利用 |
| Canary | 栈保护值是否被改变？ | 能发现所有错误，或自动修复数据 |

后三种机制不能代替正确的边界检查；它们可组合使用，作用也不相同。
